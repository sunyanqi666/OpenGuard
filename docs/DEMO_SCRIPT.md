# OpenGuard 5–8 分钟演示脚本

## 演示前准备

- 执行 `docker compose up -d db backend`，确认数据库和后端健康。
- 准备系统首页、Swagger `/docs` 和 Adminer `:8080` 标签页。
- 使用 `.env` 中的管理员账号登录，不展示密码或配置文件。
- 确认基线为 1000 条 CVE、398 条组件。

## 0:00–0:45　项目与架构

介绍 React 前端、FastAPI REST API、PostgreSQL、Docker Compose、Alembic 和教师数据导入，然后展示服务状态并登录。

## 0:45–1:30　安全态势仪表盘

展示 CVE、组件、关联和处置数量，说明严重等级、CVSS、趋势和高风险排行均来自真实数据库聚合。

## 1:30–2:40　CVE 查询、修改和删除

1. 按编号或描述查询老师指定记录，并筛选严重等级。
2. 展示详情、来源、CVSS、描述和受影响版本。
3. 修改字段并保存，刷新确认持久化。
4. 对演示记录执行删除并展示二次确认。

说明题目不要求 CVE 新增，基础验收以教师数据的查询、修改和删除为准。若时间允许，可额外展示管理员“新增 CVE”，并说明这是扩展功能，教师批量数据仍通过可信导入程序维护。

## 2:40–4:00　组件完整 CRUD

1. 新增 `pkg:maven/org.demo/openguard-demo@1.0.0`。
2. 通过名称或 PURL 查询详情。
3. 修改版本或描述，刷新验证。
4. 删除组件并确认消失。

## 4:00–5:10　创意功能

- 查看本地匹配建议并人工建立关联，强调不做漏洞扫描。
- 设置处置状态、负责人、截止日期和修复版本。
- 在审计日志中查看刚才的操作。
- 展示组件 CSV 导入和筛选结果导出。

## 5:10–6:30　完整 HTTP 请求链路

以修改组件为例，配合浏览器 Network：前端发送带 JWT 的 PATCH；FastAPI 做身份、权限和字段校验；SQLModel 更新 PostgreSQL 并写审计；事务提交后返回 JSON；TanStack Query 刷新页面。最后在 Swagger 或 Adminer 查看同一记录证明持久化。

## 6:30–7:15　质量与总结

展示 README、迁移和测试结果，说明数据导入可重复执行、没有真实密钥、没有 Agent 功能。总结基础要求和创意点。

## 随机验收应对

- 老师指定 CVE：用编号搜索并展示详情、修改、删除。
- 老师指定 Maven 组件：用 PURL 搜索；新增时使用 `pkg:maven/组织/名称@版本`。
- 问三层职责：React 负责交互，FastAPI 负责业务和权限，PostgreSQL 负责持久化。
- 问 AI：说明辅助环节及测试验证，并以“否决扫描器选型”为判断案例。
